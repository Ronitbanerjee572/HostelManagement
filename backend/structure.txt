Room Allocation Feature: Supported by GET /api/rooms (Read), POST /api/allocations (Create), and DELETE /api/allocations/:id (Delete).

Fee Tracking Feature: Supported by GET /api/fees/defaulters (Read).

Complaint System Feature: Fully optimized via GET /api/complaints/active (Read), POST /api/complaints/active (Create), PUT /api/complaints/:id (Update), and DELETE /api/complaints/:id (Delete).


Case A: If an Admin logs in
Payload sent: { "username": "admin1", "password": "admin123" }

Response received: { "status": "success", "role": "admin", "student_id": "" }

Frontend Action: Direct them to the Admin Dashboard panel where they can see all tabs (Room Allocation, Fee Defaulters list, and all complaints).

Case B: If a Student logs in
Payload sent: { "username": "ronit123", "password": "student123" }

Response received: { "status": "success", "role": "student", "student_id": "130001" }

Frontend Action: Redirect them to a restricted Student View. Store that student_id in your app state memory. When they file a complaint, auto-populate their student_id field so they can only interact with their own personal records!
